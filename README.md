# web-properties — доска направления

Направление рекламно-монетизируемых сайтов BiLingoPlus LLC. Здесь живёт
**доска**: где мы по каждому сайту, и чем это измерено.

**Доска:** https://bilingoplusllc.github.io/web-properties/
**Как мы это делаем:** https://bilingoplusllc.github.io/web-properties/hub.html

Страница закрыта от поиска (`robots.txt` плюс `noindex`): репозиторий
публичный, но индексировать внутреннюю доску незачем.

---

## Что здесь лежит

| | |
|---|---|
| `dashboard/build_web_board.py` | собирает доску; несёт **51 собственную проверку** — расхождение чисел роняет сборку, а не печатается |
| `dashboard/build_hub.py` | собирает страницу «как мы это делаем» |
| `dashboard/wp_data.py` | окна и производные величины из посуточного ряда |
| `dashboard/charts.py` | графики (инлайновый SVG, ни одного внешнего запроса) |
| `dashboard/fetch.py` | тянет свежие числа из Search Console и GA4 |
| `dashboard/pipeline.py` | снимок стадии сайтов, которые ещё строятся |
| `dashboard/data/` | данные; их переписывает бот |
| `docs/` | то, что отдаётся Pages |

Сайты живут отдельными репозиториями: [mileagecurve](https://github.com/bilingoplusllc/mileagecurve),
[gspaytables](https://github.com/bilingoplusllc/gspaytables).

## Бот

`.github/workflows/daily.yml` — раз в сутки в 05:17 UTC и по кнопке.

Тянет свежие числа → пересобирает доску → кладёт в `docs/` → коммитит, если
что-то изменилось → выкладывает на Pages.

### Ни одного секрета

В репозитории **нет секретов, и заводить их не нужно**. Ключа служебного
аккаунта не существует: организация `bilingoplus.com` запрещает их создавать
(`iam.disableServiceAccountKeyCreation`, Enforced). Запрет правильный —
скачанный ключ живёт вечно, лежит файлом и утекает молча.

Вместо ключа федерация: GitHub предъявляет свой OIDC-токен, Google меняет его
на временный и выдаёт от имени служебного аккаунта.

| | |
|---|---|
| проект | `bilingoplus-board` (номер 344965276479) |
| служебный аккаунт | `board-fetch@bilingoplus-board.iam.gserviceaccount.com` |
| пул / провайдер | `github` / `gh-actions`, issuer `token.actions.githubusercontent.com` |
| условие входа | `assertion.repository_owner == 'bilingoplusllc'` |
| кому доверяем | `attribute.repository = bilingoplusllc/web-properties` |

Доверие сужено дважды нарочно: провайдер пускает только наши репозитории, а
право выступать от имени служебного аккаунта выдано **одному** из них.

Читательский доступ выдан там, где живут данные, а не в Cloud: в Search
Console служебный аккаунт добавлен пользователем обоих ресурсов, в GA4 — ролью
Viewer на обоих ресурсах.

**Если личность не выдалась, бот всё равно работает:** `fetch.py` выходит с
кодом 2, бот идёт дальше и пересобирает доску на прежних данных, а страница
печатает их прежнюю дату. Это сознательно: доска, показывающая старые числа
под сегодняшней датой, хуже доски, которая молчит.

### Чего бот не делает

* **Не пишет пустоту.** Пустой ответ API чаще значит «запрос не выполнился»,
  чем «нуль». Если у сайта строки были, а сейчас их ноль — файл не
  переписывается, и прогон падает с этим в тексте ошибки.
* **Не сравнивает разное.** Списки сайтов в Search Console и в GA4 обязаны
  совпадать; расхождение роняет прогон, потому что отсутствующая строка в
  таблице не выглядит ошибкой и её никто не заметит.
* **Не обновляет снимок стадии.** `data/pipeline.json` снимается вручную
  `python dashboard/pipeline.py` на машине, где лежат исходники сайтов; в CI
  их нет. Доска печатает дату снимка рядом с числами.

## Собрать у себя

```bash
cd dashboard
python build_web_board.py     # -> board.html
python build_hub.py           # -> hub.html
```

Стандартная библиотека, без зависимостей. `fetch.py` — единственное
исключение: ему нужны `google-auth` и `requests`, и он нужен только боту.
Локально он скажет «НЕ НАСТРОЕНО» и ничего не тронет: федерация работает
только внутри GitHub Actions.
